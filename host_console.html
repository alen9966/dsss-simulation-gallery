01 上位机如何实现

界面使用HTML/CSS/JavaScript，Python标准库提供本机HTTP服务，再通过Vivado Tcl控制两条JTAG/VIO通道。射频通信始终由PL及AD9361完成。

网页编辑 / 显示 ↔ Python后台 ↔ JTAG/VIO ↔ FPGA载荷缓存 TX缓存 → 组帧 / BPSK / PN扩频 / 成型 → LVDS → AD9361 ↓ 同轴射频 RX缓存 ← 解帧 / 判决 / Costas / DLL / 捕获 ← LVDS ← AD9361

发送端先写备用100字节缓存，写满后在帧边界整体切换，再读取实际生效内容确认。接收端冻结下一完整载荷，读取前后核对长度及本地帧号，与发送板回读的生效内容逐字节比较。

连续抽样保留累计时间和历史记录；暂停只停止主机抽样，不停止FPGA收发。JTAG读取完整帧属于抽样，不能冒充抓取全部空口帧或统计空口丢帧率。

每设备预留独立TX/RX能力；后续可通过PS/AXI后端替换JTAG传输层。当前两个板级顶层仍分别只发和只收，尚无TDD仲裁、空口用户标识、序号/CRC和远程用户服务。

04 后续验收关卡

先完成任意载荷版本的双板实测，再接入网口/RS422/RS232和用户消息协议，最后实施每方向100 ms的时分收发。网络业务与PS同事协作；时分还需时隙同步、收发切换保护时间及失步回退，不能只加一个100 ms计数器。

硬件绝对延时、无线链路、灵敏度、PPS与几百ps同步精度均不在本页短时通信恢复验收范围内。
